# 2026-11-12

## 发布博文支持 PDF 上传 + 在线查看

- 需求「发布博文新增支持PDF文件上传功能 以及支持PDF查看」，按超集实现：
  文章可挂**一个** PDF 附件；也可正文留空、只发一份 PDF（后台校验改成
  「正文与 PDF 至少一项」）。前台默认折叠成附件卡片，点「在线预览」才创建 iframe。
- 存储方案：**复用已有的公开桶 `covers` 的 `pdfs/` 子目录**，不新建 bucket/policy。
  `schema.sql` 里 `Auth can upload/delete covers` 是按 `bucket_id` 判定的，覆盖整桶；
  实测 `application/pdf` 上传返回 200，桶没设 mime 白名单。对象 key 沿用
  `makeObjectPath` 的「时间戳+随机串」，原始文件名单独存一列（中文名不会 Invalid key）。
- 改动文件：
  - `supabase/post_pdfs.sql`（新建，幂等）：`posts.pdf_url` / `posts.pdf_name` 两列；
    **补 `Auth can delete covers` 策略**；顺手删掉验证留下的 `pdfs/__probe-%` 临时对象。
  - `src/lib/storage.ts`：`uploadPdf()`（类型 + ≤20MB 校验）、`deleteFile` 别名；
    `deleteImage()` 改为检查 `remove()` 返回的 `data` 是否真的包含该 path。
  - `src/types.ts`：`Post` 加**可选** `pdf_url? / pdf_name?`，兼容还没跑 SQL 的库。
  - `src/pages/Admin.tsx`：表单加 PDF file input / 文件名预览 / 移除；上传纳入
    `sessionUploads`，换/删/放弃编辑自动清理；`originalPdfUrl` ref 记录原 PDF。
    ⚠️ **payload 只在用到 PDF 时才带这两列**：否则数据库没加列时 PostgREST 报 42703，
    会把整个后台发文/编辑全部搞挂。保存失败遇到 42703 翻成「请先执行 post_pdfs.sql」。
  - `src/components/PdfAttachment.tsx`（新建）：懒加载 iframe + 新窗口打开 + 下载
    （Storage 跨域用 `?download=` 强制 Content-Disposition，比 `a[download]` 可靠）。
  - `src/pages/PostDetail.tsx`：正文后渲染附件卡片；`PostCard.tsx` 加 `📄 PDF` 徽标，
    纯 PDF 文章不再显示「1 分钟」阅读时长；`index.css` 补 `.pdf-*` 样式 + 720 断点。
- 验证（`npm run build` 通过；`scripts/publish/verify-pdf-feature.mjs` 本地 mock + 真实凭证）：
  - 首页 `badgeText=📄 PDF`、详情页卡片名 `演示文档.pdf`、点预览变「收起预览」、
    iframe src 带 `#toolbar=1&navpanes=0&view=FitH`、后台 `loginGate=false` /
    `#post-pdf accept=application/pdf,.pdf` / 表单提示正确；`scrollWidth 749 ≤ 764`。
  - **真实 Storage 上传 PDF 200**；公开 URL 200 / `Content-Type: application/pdf` /
    `CORS: *` / **无 X-Frame-Options、无 CSP、无 frame 报错** → 跨域 iframe 内嵌可行。
  - `GET /rest/v1/posts?select=pdf_url,pdf_name` → **400 / 42703
    `column posts.pdf_url does not exist`** → 数据库还没加列。
- 🐛 **发现既有 bug**：现有库没有 `Auth can delete covers` 策略，
  `supabase.storage.remove()` 会返回 **200 + `[]`**（不是 error），对象其实还在，
  所以旧封面/被替换的 PDF 一直清不掉且后台毫无提示。已写进 `post_pdfs.sql` 补齐，
  并让 `deleteImage()` 检查 `data.some(o => o.name === path)`，失败才 console.warn。
- ⚠️ **功能生效的阻塞项**：需用户在 Supabase SQL Editor 手动执行一次
  `supabase/post_pdfs.sql`（本地无 service_role，代跑不了 DDL）。跑完后列、删除策略、
  两个临时探测 PDF 的清理一次搞定。没跑之前普通发文仍正常（payload 兼容已做）。

  SPA fallback 服务 + 临时 Chrome，跑完自清理。
