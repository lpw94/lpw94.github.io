## 放映厅接入 OuonnkiTV（提交 17b9f73）

**需求变更**：先说「集成 Jellyfin」，用户改口「改成 OuonnkiTV」。确认后定为
**iframe 内嵌自建站点 + 地址可配置**（不做 CMS API 对接，不内置任何采集源）。

**OuonnkiTV 是什么**：LibreTV 衍生的影视聚合前端（Apache-2.0，多个 fork），本身没有媒体库 API，
靠部署者配置的苹果 CMS 视频源工作；官方环境变量前缀 `OKI_`/`VITE_`，代理在 Docker 镜像里。
它只是网页，所以集成方式只能是 iframe 或跳转 —— 这也决定了「改一个地址」的实现。

**新增 `src/lib/ouonnki.ts`**
- 地址优先级：`VITE_OUONNKI_URL`（构建期，固定不可改）→ `localStorage['ouonnki-url']`
- `normalizeUrl` 补协议头（没写协议按 https）、去尾部斜杠
- `isMixedContent` 判 https 页面嵌 http（浏览器会直接拦，提前提示）
- `OUONNKI_LOCKED_BY_ENV` 决定页面上是否显示「更改地址」

**改 `src/pages/Cinema.tsx`**
- 页头右侧加数据源切换 `.cinema-tabs`（本地片单 / OuonnkiTV），选择记进 `localStorage['cinema-source']`
- OuonnkiTV 面板三态：未配置 → 引导 + 表单；已配置 → 工具栏 + iframe；混合内容 → 橙色警告条
- 工具栏：重新加载（换 `key`）、全屏（`requestFullscreen` 容器）、新窗口打开、更改地址
- `← →` 快捷键仅在 local 模式注册，避免在嵌入模式下抢键
- iframe 加 `allow="fullscreen"` 与外链 `referrerPolicy="no-referrer-when-downgrade"`

**改 `src/lib/cinema.ts`**：`FilmSource` 的 mp4 分支加可选 `fallback`，
配合 `onError` 一次性切备用地址（为将来接转码流留的口子，当前片单未用）。

**实测（CDP，脚本 `ouonnki-check.mjs`）**
- 默认 tab = 本地片单；切到 OuonnkiTV 出现引导表单 ✅
- 填地址提交：`hasFrame=true`，iframe 684px / 699px（桌面）、523px / 340px（390 宽），无横向溢出 ✅
- `localStorage` 写入 `ouonnki-url` 与 `cinema-source`，刷新后仍在 OuonnkiTV 且地址保留 ✅
- 同源地址 `http://[::1]:5173/` 内嵌渲染正常；`127.0.0.1` 与页面不同源时被 Vite 拒（测试地址问题，非功能问题）

**上线**：main / origin/main / dev / origin/dev 均已到 17b9f73（用户侧同时提交了第 26 篇博文 139aa02）。

## 音乐播放器改 APlayer + 网易云歌单（提交 1cfc72b，已推 dev）

**需求**：把自建的 audio + 面板换成「轻量悬浮播放器」，用 MetingJS + APlayer 放一个网易云歌单。

**实现选择**：装了 `aplayer@1.10.1`（npm，非 CDN），MetingJS 的**协议**自己实现
（`src/lib/meting.ts`），不注入远程 `<meting-js>` 脚本 —— 远程脚本被墙/CDN 抽风就整个播放器空白，
且它自建的 fixed 播放器脱离 React 清理不干净。功能等价：MetingJS 本身就是
「fetch meting api → 转成 audio 数组 → new APlayer」。

**关键实测数据（都在这台机器上跑的）**
- Meting 接口：`https://api.i-meto.com/meting/api` 可用且带 `Access-Control-Allow-Origin: *`；
  `meting-api.vercel.app` 不通；`api.injahow.cn/meting/` 通但字段是旧版 `name/artist`，且可播率更低。
- **jsdelivr 本机不可达（000）**，`npm.elemecdn.com` 可达 —— 所以不引 CDN，用 npm 包最稳。
- 网易云音频域 `m801.music.126.net` 也带 CORS `*` → 浏览器端可用
  `fetch(url, {headers:{Range:'bytes=0-1'}})` 判断可播性（302→206 可播，404 是版权/VIP 限制）。
- **可播率实测（各榜前 80 首）**：原创榜 39%、飙升榜 29%、热歌榜 23%、新歌榜 21%；
  原创榜探足 100 首得 46 首可播 → 默认歌单定为 `2884035`（云音乐原创榜）。
  换自己的歌单只改 `VITE_NETEASE_PLAYLIST`。

**新增 `src/lib/meting.ts`**：`fetchPlaylist`（兼容 title/name 两套字段）→ `canPlay` 探测 →
`mapLimit` 并发 8 探测前 100 首 → 结果写 localStorage 缓存 6 小时（直链带签名会过期）。

**改 `src/components/MusicPlayer.tsx`**：`createPortal` 挂 body（祖先 `.container` 有 backdrop-filter，
fixed 会退化成相对它定位），APlayer 用 `fixed:true + mini:true`；`ap.audio` 上监听 error，
只在 `!paused` 时 `skipForward()`（预加载失败不该静默切歌），连续 8 次停手。

**改 `src/styles/index.css`**：APlayer 默认贴**左下角**（`left:0/right:0/max-width:400/z-index:99`），
覆盖成右下 20px、340 宽、`z-index:9997`。播放器盒子是 `content-box`，
所以实际总宽 = width + 18（把手 padding）+ 2（border）—— 移动端算宽度要减 44 才左右对称。
列表用 `aplayer-list-hide`（`max-height:0 !important`）控制，单独设 fixed 定位到播放条上方。
返回顶部 84→104、分享按钮 138→158 避让。

**踩坑**：APlayer 的**列表按钮是 `.aplayer-icon-menu`**（不是 `-list`），
`.aplayer-icons .aplayer-icon` 也选不中（图标是 span/button 直接带 `aplayer-icon` 类）。
测量时若在折叠动画（`transition: all .3s`）中取值会得到 115 这种中间值。

**实测（CDP）**
- 桌面 1280：折叠 86×68、展开 362×68、列表 342×242 贴在播放条上方，三者与返回顶部/分享按钮无重叠（rect 相交判断全 false）
- 390：折叠 86×68、展开 368×68、docScrollW 390 无溢出
- 点播放：`ptime` 00:00→00:03 递增（headless 无声但解码在跑）；跨路由到 `/gallery` 后 00:02→00:07 继续播、标题仍「宝船」
- 构建通过 15.3s

## 修复：播放列表展开后被侧栏卡片遮挡（提交见 dev）

**现象**：展开歌单后，右侧栏（今日运势/小游戏）卡片压在列表左半边，列表文字被切。

**根因**：`.mp-host { display: contents }` —— 这个元素**不生成盒子**，它身上的
`position: fixed + z-index: 9997` 不会建立层叠上下文；`.aplayer-body` 自己声明了 z-index 所以播放条没事，
但 `.aplayer-list` 是 `z-index: auto`，退回按 DOM 顺序参与 body 层叠，被 `.sidebar`（z-index:60）盖住。

**改法**：`.aplayer.aplayer-fixed .aplayer-list` 补 `z-index: 9997`（两处：主规则已加，媒体查询继承）。

**对照实测（CDP 1440×900，列表 x1027 w362，右栏 x1109 w220 与其重叠）**
- `list.style.zIndex='auto'`：点 (1208, 501) 命中 `fw-meta`（运势卡文字）→ 复现
- `list.style.zIndex='9997'`：同一点命中 `aplayer-list-light` → 修复
- 展开态两尺寸：桌面列表 362×242 @ (1043,566)、播放条 362×68 @ (1043,812)，gap 4px，完全对齐；
  390 宽列表 366×242 @ (12,518)、播放条 368×68 @ (10,764)，docScrollW 390 无溢出

## 放映厅加「B 站影视」tab（原计划 CCTV，实测播不了改用 B 站）

**需求**：放映厅加个带影视资源的网址。先选「CCTV 直播（电影频道）」，做完实测被拒，改 B 站。

**CCTV 方案为什做不成**（别再来一遍）
- `tv.cctv.com/live/cctvN/` 六个频道都 200、无 X-Frame-Options，iframe 能加载页面、节目单/时间轴都在

  「本时段节目暂时无法播放，请移动至移动端观看」—— 两种提示不同，说明央视网对**站外嵌入**单独做了版权拦截
- 把 iframe 撑到 1300×760 重试仍是同一提示 → 与尺寸/断点无关，是 referer/顶层域校验
- headless 截图里 video 层不合成，但这次不是合成问题：直接访问能拿到 `video` 元素并给出不同文案

  且在放映厅 iframe 里**截图能看到画面**（不是黑屏），说明官方播放器可正常嵌入播放
