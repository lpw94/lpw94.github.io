## 修复书签弹窗定位 bug（提交 fc61be7）
- 现象：/admin 书签配置的「添加/编辑书签」弹窗要滚动才看到。
- 根因：`.container` 有 `backdrop-filter`（玻璃拟态），会成为内部 `position: fixed`
  元素的包含块；该书签弹窗是唯一行内渲染（未 portal）的弹窗，`inset:0` 变成覆盖
  整个白卡容器，`align-items:center` 把弹窗推到容器垂直中点——书签越多容器越高，
  弹窗越靠下甚至掉出首屏。**教训：本项目任何弹窗都必须 createPortal 挂 body**，
  不能依赖行内 fixed。
- 修复：BookmarkAdmin 弹窗改 createPortal + 打开期间锁背景滚动。
- 用户当天还自行提交了 cd8d4d8（注释日历提示）、093272f（注释工具链接隐藏未登录访问）。


## 17:45 修复「Target container is not a DOM element」报错（非代码 bug）
- 现象：/admin 书签配置点「添加书签」抛 `Uncaught Error: Target container is not a DOM element`，
  at createPortal → BookmarkAdmin.tsx:174:9。
- 根因：dev 服务器（15:54 启动）漏掉了 17:37:03 同一秒内多次写入的最后一次变更，
  一直 Serving 编辑中间态——`open && createPortal(<jsx/>)` 的挂载目标 `document.body`
  还没加上（React 容器为 undefined 即报此错）。磁盘/已提交代码（fc61be7）本身正确。
- 排查方法：`curl http://localhost:5173/src/components/BookmarkAdmin.tsx` 对比 served transform
  与磁盘源码（jsxDEV 的 lineNumber 注释可反推源版本）； served 版缺失 scroll-lock useEffect
  且第一个 portal 无第二参数，实锤。
- 修复：`touch src/components/BookmarkAdmin.tsx` 强制 chokidar 重新 transform，无需改代码、
  无需重启 dev 服务器；浏览器 HMR 自动更新（不行就硬刷）。
- 教训：同一文件同一秒多次 Edit 后若页面行为异常，先怀疑 dev 服务器 Serving 陈旧 transform。
