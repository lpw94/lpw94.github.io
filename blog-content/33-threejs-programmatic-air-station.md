# 不用建模软件，纯代码造一座空压站：Three.js 程序化 3D 场景实战

最近接到一个需求：给工厂大屏做一个**空压站三维场景**——3 台空压机、2 个储气罐、1 台冷干机、流量计，外加一整套管路，还要能根据实时数据显示设备运行状态。手上没有 3D 模型文件，也没有建模美术，怎么办？

我的选择是：**全部用代码建模**。Three.js 的基础几何体（Box、Cylinder、Torus、Tube……）组合起来，就是一座能跑在大屏里的空压站。整个过程不需要打开任何建模软件，改参数、调位置都是改代码，改完即所见。

这篇文章记录从零到落地大屏的完整过程和技术要点。

## 一、整体思路

程序化建模的核心是"**搭积木**"：

```
参考图分析 → 场景骨架 → 设备建模 → 管路系统 → 状态系统 → 动效 → 导出 GLB → 接入大屏
```

每一类对象封装成一个工厂函数，参数化控制尺寸、位置、材质，后续任何调整（间距、颜色、流向）都只是改参数。

## 二、场景骨架：金属质感的关键

大屏场景要深蓝背景，但导出 GLB 时**背景不能进模型**（背景由页面控制），所以：

```js
scene.background = null;
scene.fog = new THREE.Fog(0x071321, 75, 190);  // 深蓝雾，远处淡出
scene.environment = new THREE.PMREMGenerator(renderer)
  .fromScene(new RoomEnvironment(), 0.04).texture;
```

`RoomEnvironment` + `PMREMGenerator` 生成 IBL 环境贴图，是金属材质有真实反射的关键——没有它，`metalness: 0.8` 的材质就是一团死灰。

## 三、设备建模：基础几何体的组合

没有复杂曲面，全部是基础几何体拼装：

- **空压机**：BoxGeometry 机身 + 圆柱储气段 + 散热格栅 + 底座
- **储气罐**：圆柱罐体 + 圆顶安全阀 + 人孔法兰 + 液位计 + 立体铭牌 + 支腿
- **冷干机**：白色机身 + 横条纹格栅
- **流量计**：主管上的异径段 + 红色标识环

材质上有个反直觉的经验：**金属件用高 metalness，非金属件用高 roughness**。储气罐第一版被环境光照得锃亮，用户反馈"太亮了"，改成灰白哑光（`roughness: 0.7, metalness: 0.1`）才对味。

## 四、管路系统：整场景最难的部分

### 4.1 管子怎么画

```js
function pipe(points, r = 0.16) {
  const curve = new THREE.CatmullRomCurve3(points.map(p => new THREE.Vector3(...p)));
  const geo = new THREE.TubeGeometry(curve, 64, r, 12);
  // ...
}
```

`CatmullRomCurve3` + `TubeGeometry`，传入折线拐点，拐角自动生成圆角弯头。

一个非常重要的设计：**气流方向 = 点位顺序**。管路走向是"空压机 → 储气罐 → 冷干机 → 流量计"，数组里的点就要按这个顺序写，后面流光动画直接沿曲线 `getPointAt(u)` 移动，方向天然正确。改流向只需调点位顺序，不用动任何动画代码。

### 4.2 拐角尖口：踩得最深的坑

多段管在直角处首尾相接时，每段 `TubeGeometry` 的端面是**开放的斜切面**，两段对不拢就会露出一个楔形尖口——截图里非常刺眼。

尝试过调封帽大小，都不理想。根治方案：**端点重合的相邻管段，合并成一根连续折线**。

```js
// ❌ 两根独立管，拐角处两个开放截面对不拢
pipe([[a, y, z], [b, y, z]]);
pipe([[b, y, z], [b, y, z2]]);

// ✅ 合并成一根，曲线在拐点自动弯成圆角
pipe([[a, y, z], [b, y, z], [b, y, z2]]);
```

### 4.3 封帽：T 口与开放端

管端开放面需要一个封帽盖住。两个规则：

- **开放端必封**：封帽用哑光平面圆盘（`side: DoubleSide`）。最初用球形封帽，结果被环境光打成刺眼的"白球"。
- **T 形接口免封**：支管起点落在主管上时，如果支管也封帽，接口处会鼓出一个"大绿球"。所以 `pipe()` 加了 `capStart / capEnd` 参数：

```js
function pipe(points, r, mat, capStart = true, capEnd = true) { ... }

// 支管起点落在主管上：起点不封，避免 T 口大绿球
pipe([[x, y, feedZ], [x, y, DRY_Z]], 0.15, M.pipeGreen, false, true);
```

### 4.4 阀门：一个组件吃下所有方向

空压机前、储气罐两侧、冷干机前后、出站主管——管子方向各不相同。统一做成**直通阀**组件，阀体按管道轴向旋转：

```js
function makeInlineValve(parent, x, y, z, scale = 1, axis = 'z') {
  const g = new THREE.Group();
  const body = mesh(cyl(0.26, 0.26, 0.72, 20), M.steelDark);  // 阀体
  body.rotation.x = Math.PI / 2;                               // 默认沿 Z 轴
  if (axis === 'x') g.rotation.y = Math.PI / 2;                // 横向管
  if (typeof axis === 'number') g.rotation.y = axis;           // 斜管：传 atan2 角度
  // 两端法兰 + 阀盖 + 阀杆 + 蓝色手轮...
}
```

函数接收"管道中心"坐标，阀体自动骑在管路上。斜管方向传 `Math.atan2(dx, dz)` 即可。这个组件迭代了三版：从锥形漏斗 → 球阀（被管道埋住只剩手轮）→ 直通阀，最终的结论是**阀门必须看起来"串"在管路里，而不是"扣"在管子上**。

## 五、状态与动效：数据驱动

空压机三态：**运行（绿）/ 停止（黄）/ 故障（红）**。状态灯放在设备前方，配 `CanvasTexture` 画的文字状态牌（"1# 运行"），导出 GLB 后依然保留。

动效两个，全部 rAF 驱动：

- **风扇旋转**：只有运行态的风扇转，停止/故障静止
- **管路流光**：每根关键管路生成若干小球，沿曲线循环移动，方向与气流一致

```js
dots.forEach(d => {
  d.u = (d.u + d.speed) % 1;
  d.mesh.position.copy(curve.getPointAt(d.u));
});
```

## 六、导出 GLB 与接入大屏

导出用 `GLTFExporter`，在页面里挂一个 `__EXPORT__` 开关，无头浏览器触发。导出前要**隐藏一切不属于模型的东西**：背景、雾、相机、HUD、地面网格、CSS2D 标签——GLB 只留几何和材质。

导出后做 magic 头校验，最终体积约 3.45MB。

接入大屏（React 项目）时不是直接加载 GLB，而是**把建模代码移植成场景模块**，因为状态要由数据驱动：

- `scene.ts`：移植全部建模与动画，暴露 `update / view / dispose / 拾取` 接口
- `index.tsx`：`compressorStates` 接实时数据，驱动三态灯；`Raycaster` 处理点击（复用原有设备弹窗）和悬停手型

```ts
canvas.addEventListener('pointermove', (e) => {
  canvas.style.cursor = pickDevice(e) ? 'pointer' : '';
});
```

## 七、踩坑清单（浓缩版）

| 坑 | 根因 | 解法 |
|---|---|---|
| 拐角楔形尖口 | 独立管段开放截面对不拢 | 合并成连续折线 |
| T 口大绿球 | 支管起点封帽 | `capStart=false` |
| 拐角白球 | 球形封帽高光过曝 | 哑光平面圆盘 |
| 阀门像悬空开关 | 阀体半径 < 管半径被埋进管里 | 直通阀体沿管轴串在管上 |
| 斜管上阀体方向错 | 组件只有 Z 轴朝向 | axis 参数按 atan2 旋转 |
| 储气罐反光刺眼 | metalness 太高 | 改灰白哑光 |
| 法兰亮成白环 | 高金属度 + 强光 | 深灰钢材质 + 提高分段 |

## 八、一点心得

程序化建模最大的优势是**可迭代**：用户每轮反馈（储气罐改并联、阀门统一样式、拐角处理细节）都是改几行参数重跑一遍。整个过程迭代了十几轮，每轮的做法都一样：

> 渲染近景截图 → 定位根因 → 最小修改 → 再渲染对比验证

不凭想象改坐标，是这类纯代码 3D 工作里最重要的纪律。

相比加载现成 GLB，代码建模的场景还能把**交互做进模型层**——点击哪台设备、哪个状态、甚至阀门的开关，都能直接映射到业务数据，这是大屏数字孪生最看重的点。
