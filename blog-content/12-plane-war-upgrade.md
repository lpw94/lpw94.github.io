## 一、这次改了点啥

博客里的飞机大战（`PlaneWar`）最早只是"能飞、能打、能躲"的雏形：两种敌机、子弹一律直上直下。玩两天就腻——敌机太乖、子弹太呆、我方一成不变。这波直接给它做了一次**内容量**升级，三件事：

- **五种性格各异的敌机**：侦察机 / 战斗机 / 蛇形机 / 炮手 / 坦克，尺寸、血量、配色、弹道、掉落率全不同，还随时间"逐渐变强"；
- **子弹改成速度向量**：敌弹有直下、有瞄准你的斜飞、有三向散射，方向和速度各不相同；我方子弹也随火力等级从单发到三发扇形；
- **我方道具升级系统**：击落敌机概率掉宝，拾取即强——🔥火力 / 🛡护盾 / ⚡急速 / ❤生命。

外加一个差点让我"发布即翻车"的经典 bug（玩家子弹只闪一帧就消失），单独拆一节讲清楚。老规矩：加了什么 / 怎么做的 / 踩了什么坑。

## 二、多机型敌机：从"大/小"到五种性格

原来的敌机只有 `big` / 小两种，区别只在血量和速度。这次把敌机抽象成一张**配置表**，机型就是表里的一行：

```ts
type EnemyKind = 'scout' | 'fighter' | 'zigzag' | 'gunner' | 'tank'

const ENEMY_DEF: Record<EnemyKind, {
  w: number; h: number; hp: number; sMin: number; sMax: number;
  score: number; glow: string; grad: [string, string]; drop: number
}> = {
  scout:   { w: 28, h: 24, hp: 1, sMin: 150, sMax: 215, score: 10, glow: '#ef4444', grad: ['#fca5a5', '#b91c1c'], drop: 0.12 },
  fighter: { w: 34, h: 30, hp: 2, sMin: 70,  sMax: 110, score: 30, glow: '#f59e0b', grad: ['#fbbf24', '#b45309'], drop: 0.18 },
  zigzag:  { w: 30, h: 26, hp: 1, sMin: 110, sMax: 140, score: 15, glow: '#a855f7', grad: ['#d8b4fe', '#7e22ce'], drop: 0.16 },
  gunner:  { w: 32, h: 28, hp: 2, sMin: 85,  sMax: 115, score: 25, glow: '#22c55e', grad: ['#86efac', '#15803d'], drop: 0.22 },
  tank:    { w: 44, h: 38, hp: 4, sMin: 40,  sMax: 62,  score: 60, glow: '#64748b', grad: ['#cbd5e1', '#334155'], drop: 0.45 },
}
```

每种机型在游戏里"性格"分明：

- **侦察机**（红）：小、快、一碰就碎，只会直直往下扔慢弹；
- **战斗机**（橙）：两格血、体格大，直下快弹，是中期主力杂兵；
- **蛇形机**（紫）：左右正弦摆动逼近，发射**瞄准你的斜向弹**——你得边躲边预判；
- **炮手**（绿）：发射**直瞄你的斜向弹**（追着打），逼你不停走位；
- **坦克**（钢蓝）：四格血最肉，一次**三向散射弹**，难啃但掉落率最高。

为了让难度自然爬坡，机型不是开局全来，而是按游戏时长**加权抽取**：前 10 秒只有侦察机/战斗机/蛇形机，22 秒后炮手登场，更晚坦克才出现。配置表一抽，生成、绘制、碰撞全从 `def` 取值，加新机型只要往表里多写一行。

## 三、子弹改速度向量：方向速度各不相同

原来玩家子弹是"每帧统一减一个固定步长"、敌弹是"每帧统一加一个固定步长"，本质都是**单向匀速**。要做变向变速，最干净的办法是把子弹统一成**速度向量 `(vx, vy)`，单位 px/秒**，每帧按 `dt` 推进：

```ts
// 玩家子弹（带速度向量）
bullets.current = bullets.current
  .map((b) => ({ x: b.x + b.vx * eStep, y: b.y + b.vy * eStep, vx: b.vx, vy: b.vy }))
  .filter((b) => b.y > -BULLET_H && b.x > -10 && b.x < W + 10)
```

敌弹也走同一套向量，只是**方向和速度由机型决定**：

```ts
// 侦察机：直下慢弹
pushEB(ex, ey, 0, 150, '#fb7185')
// 战斗机：直下快弹
pushEB(ex, ey, 0, 190, '#fde047')
// 蛇形机 / 炮手：瞄准玩家（归一化方向 × 速度）
const dx = px - ex, dy = py - ey
const len = Math.hypot(dx, dy) || 1
pushEB(ex, ey, (dx / len) * 210, (dy / len) * 210, '#e879f9')
// 坦克：三向散射（中间 + 左右各偏 30°）
const s = 170
pushEB(ex, ey, 0, s, '#94a3b8')
pushEB(ex, ey, -s * 0.5, s * 0.866, '#94a3b8')
pushEB(ex, ey, s * 0.5, s * 0.866, '#94a3b8')
```

我方子弹也不只是"更密"：火力等级 1 / 2 / 3 对应单发、双发微外扩、三发扇形（两侧带横向速度 `vx: ±130`），弹道看起来真像在"散开"。子弹对打抵消那段（玩家子弹 vs 敌弹 AABB 相交互消 + 火花）照旧保留，只是现在两边都是向量，撞起来更花。

> 小细节：把"px/帧"改成"px/秒"后，子弹速度就和帧率解耦了——高刷屏不会让子弹飞快、掉帧也不会让子弹变慢，手感更稳。

## 四、我方道具升级：击落就掉宝，拾取即强

敌机被打爆时，按机型 `drop` 概率掉落一个道具，向下飘（`95px/s`），碰到飞机就生效：

```ts
const dropPower = (cx: number, cy: number) => {
  const r = Math.random()
  const kind = r < 0.45 ? 'power' : r < 0.7 ? 'shield' : r < 0.9 ? 'rapid' : 'life'
  powerups.current.push({ x: cx, y: cy, kind })
}
```

四种道具各有用处：

- **🔥 火力**：火力等级 +1（上限 3），弹道从单发到三发扇形；
- **🛡 护盾**：6 秒免伤，机身外圈画一道青色护盾环；
- **⚡ 急速**：6 秒射速翻倍（发射间隔 `320ms → 160ms`）；
- **❤ 生命**：+1 命（上限 5）。

护盾免伤直接并进受击逻辑，和"撞弹后 1 秒无敌闪烁"并列：

```ts
const damage = (t: number) => {
  if (t < invulnUntil.current) return
  if (t < shieldUntil.current) return // 护盾期间免伤
  livesRef.current -= 1
  // ...扣命 / 结束
}
```

顶部 HUD 实时显示 `✈️分数 · ❤命 · 🔥等级 · 🛡 · ⚡`。为了避免每帧 `setState` 触发重渲染（canvas 游戏的大忌），只在 HUD 状态**真正变化**时才更新：

```ts
const syncHud = (next) => {
  const p = hudRef.current
  if (p.power !== next.power || p.shield !== next.shield || p.rapid !== next.rapid) {
    hudRef.current = next
    setHud(next)
  }
}
```

## 五、踩坑：玩家子弹只闪一帧就消失

发布前我在沙箱里没法真机试 canvas 交互，靠"构建过 + 逻辑推演"放行，结果上线后第一反馈就是：**我方子弹只闪一下就没了**。

定位过程很典型——先把游戏主循环抽成 Node 脚本逐帧模拟，立刻复现：

```
frame 0  bullets 1   (开火，子弹 y=437.9)
frame 1  bullets 0   (？？？)
```

子弹在第一帧生成、第二帧就被清空。顺着看玩家子弹的更新那行：

```ts
// ❌ 出问题的写法
bullets.current = bullets.current
  .map((b) => ({ x: b.x + b.vx * eStep, y: b.y + b.vy * eStep }))
```

这个 `map` 返回的是**全新对象字面量，只复制了 `x`/`y`，把 `vx`/`vy` 丢了**。于是第一帧过后，子弹的 `vx`/`vy` 变成 `undefined`，下一帧 `y` 算成 `y + undefined * eStep === NaN`；`filter(b.y > -BULLET_H)` 里 `NaN > -12` 是 `false`，子弹直接被过滤掉。敌弹为啥没事？因为它的 `map` 用的是 `{ ...b, x, y }` 展开，把速度字段一并保留了。

修法一行：

```ts
// ✅ 保留 vx/vy
.map((b) => ({ x: b.x + b.vx * eStep, y: b.y + b.vy * eStep, vx: b.vx, vy: b.vy }))
```

改完再跑模拟，子弹稳定累积（`1 → 3 → 4` 发），构建通过，推上去正常了。

> 这坑的普适教训：**用 `map` 做"更新并移动"的对象数组时，凡是后续帧还要用的字段，务必在返回的新对象里显式带上**。用展开 `{ ...b, ... }` 比手写字面量安全得多——手写时人脑容易默认"只改我关心的字段"，却忘了旧字段需要原样结转。

## 六、小结

这波纯做游戏内容量：五机型敌机配置表 + 速度向量子弹（方向速度各异）+ 我方掉宝升级。沉淀几条原则：

1. **行为可配置的对象用"配置表 + 一个 `kind`"建模**：加机型/武器只增数据不增分支，渲染碰撞全从 `def` 取；
2. **运动统一成速度向量（px/秒）**，和帧率解耦，手感稳；
3. **canvas 游戏的 HUD 状态要"变化时才 setState"**，否则每帧 re-render 会拖垮主循环；
4. **`map` 更新对象数组别丢字段**——手写字面量只搬了 `x/y` 漏了 `vx/vy`，导致子弹第二帧变 `NaN` 被过滤，经典又隐蔽。
