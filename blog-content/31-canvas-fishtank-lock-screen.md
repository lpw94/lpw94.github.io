> 这是博客「自身改造」系列的一篇（前几篇见 [建站实录](/post/blog-build-log)、[技术要点拆解](/post/blog-tech-highlights)、[互动化改造](/post/blog-interactive-features)）。这次做的东西看起来最不「实用」：把首页的锁屏遮罩，从一张静态渐变换成了**一缸实时演算的生态鱼**。没有图片素材，没有 Three.js，没有动画库，只有一个 `<canvas>` 和 600 行 TypeScript。
>
> 写下来是因为过程里踩的三个坑都很典型：**分层顺序决定景深**、**光柱画不好会变成竖条纹**、**手机上鱼全被卡片挡住**。这些和「会不会画画」没关系，全是可以复用的工程判断。

## 一、先定分层：渲染顺序就是景深

Canvas 没有 z-index，谁后画谁在上。所以第一件事不是画鱼，是把「从前到后」的顺序写成一张表，然后每一帧严格按这个顺序重画：

| # | 图层 | 作用 | 是否动 |
| --- | --- | --- | --- |
| 1 | 水体渐变 + 左上光团 | 底色，越往下越暗 | 静态 |
| 2 | 水面波纹 | 顶部三条正弦曲线 | 每帧 |
| 3 | 光柱 | 柔和的斜射亮带 | 整层缓慢漂移 |
| 4 | 浮游微粒 | 水里飘的悬浮物 | 每帧 |
| 5 | 沙床 + 卵石 | 缸底，收住画面下沿 | 静态 |
| 6 | 水草 | 贝塞尔叶片，顶端摆动 | 每帧 |
| 7 | 气泡 | 带高光的小圆，横向漂移上升 | 每帧 |
| 8 | 鱼群 | 主角 | 每帧 |
| 9 | 涟漪 | 点击反馈，画在最上 | 每帧 |

`render()` 就是这九行，几乎不用注释：

```ts
const render = () => {
  ctx.clearRect(0, 0, w, h)
  drawWater(); drawSurface(); drawRays(); drawMotes(); drawSand()
  drawWeeds(); drawBubbles()
  for (const f of fish) drawFish(f, time)
  drawRipples()
}
```

`time` 是全局累积秒数，所有摆动都从它派生。这样水草、气泡、鱼尾的相位天然同步，不需要给每个对象单独维护计时器。

## 二、鱼怎么「活」起来

### 一条鱼的数据

```ts
type Fish = {
  x: number; y: number
  dir: 1 | -1        // 朝向
  speed: number      // 水平速度 px/s
  vy: number         // 垂直速度
  ty: number         // 想游到的高度
  len: number        // 体长
  kind: number       // 配色
  phase: number      // 摆尾相位
  far: boolean       // 远景鱼
}
```

画鱼时先 `translate` 到鱼的位置，再 `ctx.scale(f.dir, 1)` —— **左游的鱼不用另写一套路径**，把坐标系水平翻一下就行，省掉一半代码。身体是两条对称的贝塞尔曲线，尾鳍、背鳍、腹鳍用二次曲线，小丑鱼的白条纹靠 `bodyPath() + clip()` 裁在身体里，不会溢出轮廓。

尾鳍摆动幅度由 `Math.sin(f.phase * 2)` 决定，`phase` 随速度增长：`f.phase += dt * (2.2 + f.speed / 90)`，游得快的鱼尾巴摆得也快。

### 巡游与躲鼠标

垂直方向用一个**阻尼弹簧**追目标高度，比「匀速上下移动」自然得多：

```ts
f.vy += ((f.ty - f.y) * 1.1 - f.vy * 1.5) * dt
f.y  += f.vy * dt
if (Math.random() < dt * 0.28) f.ty = pickTy()   // 偶尔改主意
```

`dt * 0.28` 意味着平均 3.5 秒换一次目标高度，鱼不会像电梯一样直上直下。碰到左右边界翻转 `dir`，上下边界则把 `vy` 反向减半，像被缸壁轻轻弹回来。

躲鼠标是纯几何：距离小于 175px 时按反方向施加推力，小于 95px 且鱼正朝着鼠标游时直接掉头。这里用的是 `pointermove` 而不是 `mousemove`，触屏也能触发。

### 景深

每 4 条里有 1 条 `far: true`：体长乘 0.74、速度乘 0.8、`globalAlpha = 0.55`。就这三行，远近层次立刻出来了，比调色更管用。鱼的数量按画布面积算，钳在 7~15 条：

```ts
const fishCount = Math.round(Math.min(15, Math.max(7, (w * h) / 62000)))
```

## 三、交互：点一下水面会冒气泡

`pointerdown` 时往 `ripples` 推一个半径 6、life 1 的圆环，同时生成 7 个气泡；圆环每帧 `r += 130 * dt`、`life -= dt * 0.85`，淡出即从数组里删掉。

一个容易被忽略的细节：**气泡必须有数量上限**。点击会不断往数组里塞元素，用户连点几十下，每帧要画的圆就越来越多，帧率会缓慢下滑。所以加了兜底：

```ts
if (bubbles.length > 90) bubbles.splice(0, bubbles.length - 90)
```

## 四、坑一：光柱画成了竖条纹

第一版是每帧画 5 个梯形多边形，边缘是**硬边**，截图里像五道半透明的玻璃隔板，完全不像水下的丁达尔光。

改法不是给多边形加渐变（试过，仍然有可辨的直线边界），而是**把整层光柱预渲染成一张离屏位图，并在这张图上做模糊**：

```ts
rayLayer.width  = Math.round(w / 2)   // 半分辨率
rayLayer.height = Math.round(h / 2)
rc.scale(0.5, 0.5)
rc.filter = 'blur(7px)'               // ≈ 屏幕 14px
// ...画 5 条梯形...
rc.filter = 'none'
```

之后每帧只剩一次 `drawImage`，顺带用 `sin(time * 0.13)` 让整层做极缓慢的横向漂移。半分辨率还有个额外好处：模糊半径等效翻倍，模糊本身的开销也降到四分之一像素量。

> 这条经验可以推广：**凡是「大面积、低频率、边缘要软」的背景层，都值得预渲染成位图**，别在主循环里反复算路径。

## 五、坑二：手机上鱼全被卡片挡住

锁屏卡片居中，宽 `min(452px, 100vw - 32px)`。桌面 1440×900 时它只占中间一小块，鱼随便游都看得见；390×844 时卡片高 389px，几乎把中间整条水带吃掉了，截图里上下空空荡荡，只剩两条鱼贴着边。

修法不是缩小卡片（解锁表单已经压得很紧），而是**限制鱼的目标高度**：

```ts
const pickTy = (): number => {
  if (w >= 720) return rand(h * 0.12, h * 0.76)
  // 窄屏：只去卡片上方 / 下方两条水带
  return Math.random() < 0.55
    ? rand(52, h * 0.2)
    : rand(h * 0.74, h * 0.8)
}
```

55% 概率选上带、45% 选下带，鱼偶尔还会穿过卡片区域（被玻璃虚化成光斑），比「严禁进入」更自然。

顺带一提卡片本身：`backdrop-filter: blur(14px) saturate(1.15)` 会让游到卡片后面的鱼变成一团柔和的橙色光斑，「隔着缸壁看鱼」的感觉就是这一行给的。另外还有一层 `.tank-glass`：斜向反光 + 四角暗角 + `inset` 阴影，负责玻璃质感，`pointer-events: none` 保证不挡点击。

这里还有个老坑：项目里带 `backdrop-filter` 的容器会成为 `position: fixed` 的包含块，所以锁屏遮罩必须 `createPortal` 挂到 `document.body`，不能留在主布局树里，否则 `inset: 0` 会相对某个祖先定位。

## 六、坑三：动画跑满 CPU

锁屏是遮罩，用户可能挂着一整晚不解锁。所以性能与「安静」比炫技更重要：

- **DPR 上限 2**：`canvas.width = w * Math.min(devicePixelRatio, 2)`，再高没有肉眼收益，只是多画几百万像素。
- **`dt` 钳到 0.05s**：切回后台再回来时，`requestAnimationFrame` 的 `ts` 会跳一大截，不钳住的话鱼会瞬间「瞬移」到缸壁。
- **`visibilitychange` 停循环**：页面隐藏时 `cancelAnimationFrame`，回来时把 `last` 归零重新起。
- **`prefers-reduced-motion`**：系统开了「减少动态效果」时，不启动 rAF，只画一帧静态场景（`time = 0.7`），交互仍然可用。
- **`ResizeObserver` 重铺场景**：尺寸变化时按新的 `w/h` 重新 `seedScene()` 和 `buildRays()`，鱼群密度、水草高度、光柱宽度都是按当前尺寸算的。
- **组件卸载清理**：rAF、ResizeObserver、5 个事件监听全部在 `useEffect` 的 cleanup 里注销。

无头浏览器实测（1440×900 与 390×844）：帧率约 **61fps**，canvas 正好铺满视口，`document.documentElement.scrollWidth` 与视口宽度相等，没有横向溢出。

## 七、解锁逻辑一行没动

再好看的背景也只是背景。锁屏仍然是那道随机算术题（+ / − / ×，结果保证非负整数），输对才 `onUnlock()`；问候语按小时变、标语随机抽、时钟每秒跳。顶栏的 🔒 按钮手动触发，空闲 5 分钟自动锁——**首访不自动锁**，这条是之前专门改过的，别让第一次来的读者以为站点坏了。

## 小结：三条可以带走的经验

1. **Canvas 场景先定图层表，再写代码**。绘制顺序就是景深，顺序一乱，怎么调色都像贴纸。
2. **软边大面积背景预渲染成离屏位图**，主循环只 `drawImage`；硬边多边形 + 透明度渐变不是「柔光」，是「玻璃隔板」。
3. **响应式不只是缩放尺寸，还要重排内容**。手机上把鱼的目标高度分到两条水带，比等比缩小一整缸有效得多。

以及一个不太技术但很实在的体会：**给自己的站点做点没用的东西，往往是练 Canvas / 动画 / 性能最好的方式**——没有产品需求、没有验收标准，唯一的指标就是「看着舒服」，反而会逼你把每一帧都想清楚。
